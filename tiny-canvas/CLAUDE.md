# Tiny Canvas — game/app-level guide

A polished kids coloring app. Pick a page, color it in, save it.
Shipping to **App Store + Google Play + the web**, all from one codebase
via Capacitor.

**Read these first:**
- The repo-root [`../CLAUDE.md`](../CLAUDE.md) for project-wide rules
  (no build system on the *static-site* games; absolute URLs for SEO;
  GoatCounter beacon; ad-free / kid-friendly branding).
- The repo-root [`../DESIGN.md`](../DESIGN.md) for tokens, type stack,
  drawer pattern, animation timings, and voice — **all of which were
  the design source for this app**.

## What's different about Tiny Canvas (vs. the static-site games)

Tiny Canvas is the **first madderverse product with a build system**.
Every other game in the hub is pure HTML/CSS/JS served as-is by GitHub
Pages. Tiny Canvas:

- Is wrapped with **Capacitor** for iOS + Android distribution.
- Has a `package.json`, `node_modules/`, and (after first `cap add`)
  `ios/` + `android/` directories.
- Still works as a plain static site at `madderverse.org/tiny-canvas/`
  (the web build is just the HTML/CSS/JS — no bundler).

The web version is fully independent of the native build. Local dev is
still `python3 -m http.server 8000` from this directory; you only touch
Capacitor when you're packaging for a store.

## What it is

- 4 screens, swapped via the `[hidden]` attribute on `<main class="screen">`:
  **title → picker → draw → gallery**, with a detail modal on the gallery.
- 6 line-art templates (BLANK + smiley sun + friendly cat + rocket +
  fish + tiny house). Each is a `viewBox="0 0 800 800"` SVG drawn in
  `currentColor` strokes; rendered as a `pointer-events: none` overlay
  above the kid's canvas so the kid colors UNDER the lines.
- Brush + eraser, 3 sizes, 12-color onioncore-aligned palette.
- localStorage gallery, cap 60 entries. Each save composites the
  canvas + line-art into a PNG dataURL, stored as a record:
  `{ id, name, template, date, png }`.
- Web Audio synthesized SFX (tap / save / erase / swoosh). No audio files.
- PWA: manifest + theme-color + Apple PWA chrome. `beforeinstallprompt`
  reveals the INSTALL APP button on supported Chromium browsers.

## Architecture (`game.js`, top → bottom)

| Section | What lives there |
|---|---|
| **CONFIG** | `STAGE_W=800`, `STAGE_H=800`, `COLORS` (12), `SIZES` (8/18/32), `MAX_HISTORY=20`, `SAVE_MAX=60`, `STORAGE_KEY` |
| **STATE** | `screen`, `templateId/Name`, `currentColor/Size/Tool`, `isDrawing`, `lastX/Y`, `history`, `dirty`, `savedId`, `dpr` |
| **AUDIO** | Lazy `ensureAudio()`. `sfxTap` (brush-down sine blip), `sfxErase` (high-pass noise), `sfxSave` (two-tone bell), `sfxSwoosh` (band-pass noise). All silent-fail. |
| **CANVAS SETUP** | `setupCanvas()` resizes the backing store to `STAGE_W*dpr × STAGE_H*dpr` and rescales the 2D context. `getPos(e)` converts pointer coords to logical 800×800 units. |
| **HISTORY** | `pushHistory()` snapshots the canvas via `getImageData` before each stroke (cap `MAX_HISTORY=20`); `undo()` restores the top of the stack. |
| **DRAWING** | Pointer-event handlers (`onPointerDown/Move/Up`) draw a dot on tap + a line on drag. `currentTool === "eraser"` switches `globalCompositeOperation` to `destination-out`. `setPointerCapture` keeps strokes glued to one finger. |
| **TEMPLATES** | `loadTemplate(tpl)` injects the SVG into `#lineArt`, updates the title, clears the canvas. |
| **UI BUILDERS** | `buildPicker`, `buildPalette`, `refresh*` (sync DOM with state) |
| **SCREENS** | `showScreen(name)` toggles `[hidden]` on the four `<main class="screen">` containers + fires `sfxSwoosh`. |
| **GALLERY** | `loadGallery / persistGallery` (localStorage JSON), `composePng()` (offscreen canvas: paper → strokes → line-art SVG → PNG dataURL), `saveDrawing`, `renderGallery`, `openDetail / closeDetail / deleteCurrent / exportCurrent`. |
| **PWA** | `beforeinstallprompt` listener — reveals `#btnInstall` on the title screen. |
| **KEYBOARD** | Ctrl/Cmd+Z = undo (only on the draw screen). |
| **INIT** | `init()` runs on `DOMContentLoaded`: setup canvas, build UI, wire handlers, attach resize-aware re-init. |

## The drawing model

```
+------------------------------------+
|  .canvas-wrap (dark teal frame)    |
|  +------------------------------+  |
|  | #drawCanvas       z = 1      |  |   ← kid's strokes
|  | (paper background, 800×800   |  |
|  |  logical, DPR-scaled)         |  |
|  +------------------------------+  |
|  | .line-art (SVG overlay)      |  |   ← printed lines
|  |  pointer-events: none        |  |     (stay above strokes)
|  |  z = 2                        |  |
|  +------------------------------+  |
|  | .canvas-overlay-btn (undo)   |  |   ← floating control
|  |  z = 2                        |  |
|  +------------------------------+  |
+------------------------------------+
```

**This is the standard coloring-book pattern.** The kid's color goes
UNDER the lines, so strokes outside the lines are visible (a mistake
they can erase). The line art is `currentColor` so it inherits
`var(--line-ink)` from the parent — never re-stroke individual
elements with explicit colors inside the SVG.

## Adding a new template

Append to `window.TINY_CANVAS_TEMPLATES` in `templates.js`. Each entry is
`{ id, name, svg }`. The SVG must:

1. Use `viewBox="0 0 800 800"` (matches the canvas logical size).
2. Set `fill="none"`, `stroke="currentColor"`, `stroke-width="6-10"`,
   `stroke-linecap="round"`, `stroke-linejoin="round"` on the root
   `<svg>` — child elements inherit.
3. Have **no background fill** — the canvas's `--paper` color is the
   background; the SVG just draws lines on top.
4. Keep strokes thick enough that color stays cleanly enclosed at
   normal viewing size (6-10 stroke-width works at 800px logical).

The picker auto-discovers the array, so no other code change is needed.

## Capacitor setup (first-time, per machine)

You need **Node 18+**, **Xcode** (for iOS), **Android Studio** (for
Android), and **CocoaPods** (`brew install cocoapods` on macOS) before
the iOS build will work.

```bash
# from inside tiny-canvas/
npm install
npx cap add ios       # generates ios/ — commit it
npx cap add android   # generates android/ — commit it
npx cap sync          # copies the web build into the native projects
```

After that, day-to-day:

```bash
npx cap sync          # after any web change you want to test natively
npx cap open ios      # opens Xcode
npx cap open android  # opens Android Studio
```

The web version still works without any of the above — just
`python3 -m http.server 8000` and open `http://localhost:8000/`.

## Brand alignment (per DESIGN.md)

- Palette uses canon `--pink: #ff2e88`, `--teal: #00ffcc`, `--bg-deep:
  #06141a`. **Don't drift to the hub's `#ff00ff` magenta** — Tiny
  Canvas follows canon, not hub.
- Type: Bungee titles, VT323 status text, Press Start 2P tiny labels.
- Bottom-sheet drawer pattern on phone, side-rail on tablet+ — same
  geometry and timing as Pootery.
- One **explicit deviation** from canon: the canvas paper itself is
  light (`--paper: #fbfaf6`), not onioncore dark. The chrome around
  it stays dark. This is documented in DESIGN.md §16.

## Things that bite

- **DPR scaling matters.** The canvas backing store is `STAGE_W*dpr ×
  STAGE_H*dpr`, the 2D context is scaled by DPR, and pointer coords
  are normalized in `getPos()` to logical 800×800 space. Don't draw
  in physical pixels — everything is logical units.
- **`getImageData` can throw** under cross-origin / taint rules. The
  history code wraps it in try/catch; if the snapshot fails the kid
  just won't be able to undo that stroke. Don't introduce
  cross-origin images on the canvas without considering this.
- **`composePng()` is async** because it has to inline-render the SVG
  via a Blob URL → Image roundtrip. Don't `await` it on the
  pointer-event path — only on save.
- **Audio is gesture-gated.** The first `pointerdown` / `keydown`
  unlocks the `AudioContext`. Sound on the title screen will be silent
  until the kid taps something.
- **`localStorage` is capped** (~5MB on most browsers) and 60 PNG data
  URLs at 800×800 will fill that fast. The `SAVE_MAX=60` cap exists
  to keep the gallery from blowing the quota. When wrapping for
  native, swap to `Filesystem.writeFile` with the dataURL parsed back
  to a Blob — much higher ceiling.
- **The line-art SVG is rendered twice**: once as a live `<div>`
  overlay (for the kid to see while coloring), once as an `<image>`
  inside `composePng()`'s offscreen canvas (so saved PNGs include the
  lines). If a template's SVG uses external resources (filters,
  patterns), they have to be inline — the offscreen Image load only
  sees what's in the SVG string.
- **`viewport-fit=cover` is set** but `user-scalable=no` is **not** —
  unlike Pootery. We allow pinch-zoom so kids can get close to a
  specific area of a coloring page. Capacitor's iOS WebView respects
  this.
- **The hub doesn't link to Tiny Canvas yet.** When v1 ships, add a
  `.game-card` to the root `index.html`'s `<nav class="game-grid">`
  and drop a `cover.jpg` here.

## Roadmap

Things the MVP defers:

1. **Native save-to-photo-library.** Web export uses an `<a download>`
   click. Native needs `Filesystem.writeFile` + permission flow.
2. **More templates.** Six is enough to demo the loop. Aim for ~20
   for the store launch.
3. **Cover art + screenshots.** `cover.jpg` for the hub, plus
   1290×2796 iPhone screenshots and 1080×1920 Android screenshots for
   the store listings.
4. **Splash screen artwork.** `capacitor.config.json` references a
   splash but no `splash.png` is shipped yet.
5. **App icon raster set.** `icons/icon.svg` is the source; iOS +
   Android need a full size matrix generated.
6. **In-app purchase (optional).** If we go premium-template-packs
   route. `@capacitor/google-play-billing` + `@capacitor/store-kit`
   aren't wired yet.
